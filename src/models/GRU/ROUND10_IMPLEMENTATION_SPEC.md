## 0. Rules that apply to every change

- Work only inside `src/models/GRU/`. Never modify anything under `data/`. Never commit, push, stash, checkout or tag (the owner commits manually).
- Lab server runs Python < 3.12. Forbidden: PEP 701 nested-quote f-strings (use `.format` or `%` when quotes nest), `dict | dict`, `str.removeprefix/removesuffix`, `hashlib.file_digest`, `match` statements. Keep the `torch.load(..., weights_only=False)` fallback pattern from `runio.py`.
- Behaviour preservation: every new knob defaults to the legacy behaviour so an unchanged environment reproduces Round 9 numbers bit-for-bit. The only deliberate numeric change is the H9 anchor off-by-one fix.
- Knob plumbing (all five places, every knob): `config.py` env read -> `RUN_NAME_BASE` tag (config.py ~877-937) -> `run_config.json` snapshot (runio.py ~49-117) -> `eval_checkpoint.env_from_config` / `KEYS` (eval_checkpoint.py ~40-72) -> `export_results.leaf_name/family` (export_results.py ~37-144).
- Checks: one script per hook in `round10_checks/check_<hook>.py`, runnable from `src/models/GRU` with `python round10_checks/check_<hook>.py`, no training, prints PASS/FAIL per item, non-zero exit on FAIL. Champion checkpoint for regression checks: `calit2-thermal-wiki/round9/GRU-runs-round9/runs/2026-08-06_forward_direct_W10_Tin-anchor_l1_w1-6-3_oth-abs_h160x1dp0.2_ep2000_vs2_seed7/` (checkpoints/best_gru_variant_forward_direct.pth, run_config.json, variants/forward_direct/{meta.json,predictions.npz,summary_errors.csv}).

### H2 — per-file T_avg loss mask + B7 + B8
1. Env knob `TAVG_MASK`: `""` legacy; `split` = json `tavg_mask` list; `random:<seed>` (B7) = same NUMBER of training files as the split mask has among training files, drawn uniformly from training files with that seed, validation mask = the json's masked validation files; `valonly` (B8) = training labels original, validation mask = json's masked validation files only. ### H3 — validation-side scoring, vetoes, SEAL_TEST, `eval_checkpoint --set`
1. `eval_checkpoint.py --set val|test` (default test). `val` builds datasets from the checkpoint's validation files (respecting `SPLIT_NAME`, `TAVG_MASK` from its run_config) and writes `summary_errors_val.csv` + `predictions_val.npz` (or to `--out`), never overwriting test artefacts. 2. `test_model` (evaluate.py ~393-440): new columns `JumpSteps_gt2C_ToTa`, `JumpSteps_gt1C_ToTa` (T_outer and T_avg only, first transition t0->t1 counted by prepending `row0`, ~465-467), `Err_step1_<ch>`, `MaxErr_1_5_<ch>`; old `JumpSteps_gt2C` unchanged. Masked validation files: T_avg metrics NaN and excluded from aggregates.
3. `SEAL_TEST` env (default `"0"`). With `1`, main.py skips the test set entirely, scores the validation set with the same `test_model` path, writes `Val_MAE_<ch>`, `Val_RMSE_<ch>`, `Val_JumpSteps_*` to meta.json, `"sealed": true` to run_config.json and meta, and never writes any `Test_*` key. `done.flag` resume (main.py ~103-131) asserts that a sealed meta is not reused as test-scored and vice versa.
4. Pure aggregate function (evaluate.py or `round10_metrics.py`): per-channel MAE over scored files, `(T_outer+T_avg)/2`, blow-up flag (mean of three channels > 1.5 C), both JumpSteps totals.

### 5.1 Protocol, migration and identity

`protocol()` reads `prereg/round10_v4.json`. The frozen v3 JSON and its historical experiment-log entry remain intact; `prereg/ROUND10_V4_AMENDMENT.md` records why v4 was introduced after the owner stopped early v3 training.

- Formal runs use `RUN_PREFIX=r10v4`; results and journal use `runs/_round10_v4_results/`. Smoke uses `r10v4smoke_<arm>` and retains records in `runs/_round10_v4_smoke/`.

- Test reads remain B6 and F11 through the report capability and journal. Migration and preflight do not inspect test CSV contents. No test-result-dependent recipe change is permitted.
